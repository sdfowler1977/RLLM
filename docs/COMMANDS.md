# Command handling

Investigation runs within the normal command path. The app follows the goal, identifies unknowns, gathers relevant evidence, evaluates explanations, applies findings and checks the result. Ordinary requests, assigned tasks, callable children, refinement and compaction use that shared method.

Investigation forms are optional: an ordinary conversation request starts its question automatically. An agent with the hypotheses permission can record the plan and findings through the usual reviewed operations. A requested implementation language belongs in the authored constraints. The same records supply the optional design-brief projection and reviewed Markdown export, alongside the existing complete journal JSON. See [Question and design process](QUESTION-PROCESS.md) for the distinction between authored plans, actual returned evidence and separate analysis/implementation contexts.

Detailed operation reference follows the current permissions, source configuration and request phase. Baseline/probe work uses its configured operations; proposal/composition uses captured evidence; compaction summarizes the supplied conversation. A turn supports eight reviewed operations and a fresh native instruction starts a new allowance.

Additional guidance is available under Agent settings → Instructions and preferences. Saved user skills supply their selected instructions. App settings → Files and storage groups the configured source controls. Drafts and the active conversation remain available through navigation.

Connection import preserves saved settings, prior configurations and actual returned records. Identity, policy, source and permission checks follow the current configuration. Optional MCP settings expose discovered server names/schemas through the ordinary reviewed call path.

WebDAV operations carry exact single-use request ownership through manual, model and child work. Requests retain their connection, workspace, policy, revision and child context. Creation/update flows verify contents by readback; native callbacks return the transport ticket for success and failure.

Provider-hosted search uses its configured provider route in eligible operation phases. Owned returns automatically retain reported query/title/URL/error metadata in the question journal, with exact projection bytes, digests and coverage. Query-only pauses retain continuation context; continued results correlate with the prior query. Finite comparisons, native views, refinement and reviewed exports use the same metadata records.

Every ordinary model request includes the saved model/connection catalog and permitted child-agent entries, with exact indexes, effective routes, roles, specialties and tools. Select an agent index, a unique configured model/connection identity or a declared role/specialty. A selector-free task uses the first routable permitted child in configured order. Approval shows the actual selected child and model and captures that review identity.

A rejected delegation proposal returns the controller reason through one bounded feedback request. Fresh native instructions restore that feedback allowance. Owned child responses/failures, native rejection and interruption have explicit status and linked question identity. The captured parent retains an actual child return through continuation preparation errors. Ordinary source observations and child-operation records remain available through their established views.

Delegate route validation and response admission settle in the requesting context. Admission precedes child start and request timing. Controller errors pass through captured parent frames, with each actual return retained in its corresponding context. Resources and conversation controls provide the current response allowance.

The request catalog includes each queued delegation review and its originating question. A resumed task uses that recorded question for the child relationship and parent continuation. Review metadata is created by the controller when adopting a model proposal.
