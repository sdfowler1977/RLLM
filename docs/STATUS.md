# Current implementation

Configured WebDAV storage now supports optional app-owned S256 browser and device-code authorization through the existing public-client engine, with a typed model/storage owner and explicit refresh. Storage tokens are bound to the saved destination, trust identity and authorization settings. Manual credentials are retained and restored only by explicit choice; expired, uncertain or changed grants never fall back silently. Model authorization, automatic model refresh, primary replies, pending-transfer ownership and optional voice remain separate. Authorization review discloses credential use and destination; opening it retires an owned microphone session. Provider-native cloud file APIs and SMB remain open. Voice and microphone settings are directly available from App settings and conversation menus. Preferences and permission status remain accessible without a speech server or model. Saving preferences starts no capture or network request; explicit manual/open-microphone review starts a session. Settings stop only an owned voice session, retain primary replies and manual speech proposals, and share typed range validation with capture. Optional generic storage key/token headers now cover manual WebDAV and both payload formats, with default Bearer, configurable header/prefix, retained username/password or unauthenticated mode, atomic refusal and no credential replay. Export omits secrets and saved transfers retain their pinned credentials. Legacy pending project and artifact transfers now preserve their saved certificate DNS hostname for writes, retry probes and exact readback while retaining the configured socket route and trust checks. The shared TLS identity helper handles binary request framing, changes only the header authority and preserves opaque payload bytes. Invalid, unencrypted or changed identities refuse before transport without discarding the pending source. Current streamed transfers keep the same identity behavior. Storage now accepts installed document providers through the generic Android picker and account setup, with separate local-phone and provider access checks. Owned read grants are tracked across selections; disconnect preserves unrelated writable and folder grants, confirms completed releases and retains failures for explicit retry. Late picker returns cannot acquire grants, failed state adoption releases only newly acquired grants, external opening creates no orphaned read, and disconnect or read refusal preserves unrelated primary work. Existing provider settings and the previous navigation action remain compatible. Application-owned cloud OAuth and SMB remain separate open capabilities. Optional background voice now uses explicit current-session consent, a private microphone/playback service, visible notification Stop, a bounded wake lease and current permission/owner/expiry checks. Activity return preserves the live owner; task/activity destruction and process loss retire it. Background speech retains configured routes and the primary answer while ordinary previews wait for the visible app. Native capture start and stop are serialized. Background callbacks and activity return preserve current core drafts, and service stop preserves ordinary previews. Optional device-code authorization now uses configured endpoints and explicit rate-limited checks, rejects stale phase callbacks, preserves API keys and reuses the existing owned refresh lifecycle. Private device codes remain process-owned and restart never replays them. Useful model commentary remains visible when one request is embedded in prose. Explicit recovery stages its exact request for one-time approval with current profile, task and permission checks; saved automatic grants cannot dispatch it. Response details preserves raw text and branching. Built-in search can explicitly review the alternative source once without rewriting the query or borrowing custom credentials. Memory-refused voice service requests now clear their matching phase and leave the loop explicitly paused. Primary text answers and consent remain available; only explicit resume starts another microphone. Separate request reviews, operations and tasks pause capture without replacing their proposal or running owner. A held completed utterance cannot submit recognition over that work; explicit resume starts a fresh microphone afterward. Failed speech preparation, including an oversized answer or full media storage, also pauses voice while preserving the complete primary text and specific explanation. Voice review now reports its actual waiting state, preserves unexecuted proposals when dismissed, pauses cleanly after rejection and starts a fresh microphone only on explicit resume. Actual service admission advances recognition/synthesis status, and manual transcription stays in the composer. Audio route disconnection and speech focus loss now stop owned foreground capture/playback, invalidate the current voice session and preserve unrelated text/local work and in-flight primary answers. Speech explicitly pauses for transient ducking, and stale route/focus callbacks cannot stop a new owner. Scene rasterization now uses bounded shared CPU workers, disjoint row bands, preserved draw order and deterministic pixels. Measured CPU and memory limits retain a single-worker fallback, and queued/active cancellation releases owned workers before returning. Packaging validates complete aligned payload hashes/lengths/CRC and retries alignment at most once before signing. Returned GLB triangle geometry now has an owned interactive in-app software viewport with Rust accessor, sparse-data, hierarchy, transform, material and source validation. Native orbit, zoom and reset controls present actual depth-tested geometry. Unsupported scenes retain their original files for export. Optional foreground spoken interruption now uses explicit consent, device echo control and the same Rust PCM capture across playback interruption, preserving leading speech. Saved microphone review controls now reach their actual settings. Unsupported echo control retires only the optional watch; explicit Speak now and ordinary text remain available. Direct binary service submissions now stream complete 200/201 responses to owned files, with configured limits, exact statuses, scoped fallback and expiry cleanup. Accepted, partial, redirected, truncated or uncertain submissions are not replayed. Selected files up to 64 MiB now import and upload in bounded chunks through configurable binary, multipart and JSON requests, with file ownership, shared storage reservations and scoped GET upload refusal. Optional voice conversation now supports explicit Speak now interruption, immediate Stop for pending playback and stale callback isolation. Missing CPU metadata discovers bounded multicore host task concurrency. Optional generic S256 authorization includes owned automatic refresh and browser-flow recovery while retaining API-key settings. Read-only ACP v1 sessions share actual workspace operations. Configurable recognition/synthesis, image/video/scene/document routes, fallbacks, jobs, streamed artifacts, ordinary text, local work and captured primary/child returns remain part of the same app. Extra services remain optional.
